## 二、查实的问题

### 1. typecheck 的 7 条错误（已修，但值得记根因）

**症状**：`pnpm typecheck` 报 7 条，全是「找不到模块」与「属性不存在」：

```
src/index.ts(20,21)   TS2307 Cannot find module '@deepseek-ai/dsh-client-connection'
src/index.ts(173,26)  TS2339 Property 'connection' does not exist
src/index.ts(177,21)  TS7006 implicit any
src/client/index.ts(104,7)(104,58)(113,7)(113,66) TS2339 Property 'slots' does not exist
```

**根因（既有缺陷，非某次改动引入）**：

- `@deepseek-ai/dsh-client-connection` **从未进过 `package.json`**（`git log -S` 查证）。
  它在 lock 里只是**传递依赖**，而 pnpm 不把传递依赖提升到顶层 → `src/index.ts:20` 的
  type-only import 一直解析不到。**「lock 里有」不等于「能 import」。**
- `ctx.slots` 的 Context 增强来自 `@deepseek-ai/dsh-client-ui-renderer/client`，该包同样
  从未进 devDeps。删掉 `dsh-client-runtime` 之后这 4 条才暴露出来。

**已采用的修法**（`b0367ad`）：

1. devDeps 加 `@deepseek-ai/dsh-client-connection` 与
   `@deepseek-ai/dsh-client-ui-renderer`，**钉精确 `0.2.0-rc.1`**；
2. `src/client/index.ts` 加 `import type {} from '@deepseek-ai/dsh-client-ui-renderer/client'`；
3. `pnpm install`。

**两个坑，后续别踩**：

- **devDeps 写范围会装错版本**：写 `>=0.1.7-rc.2 <0.3.0` 时 pnpm 的 prerelease 选择规则
  会挑到旧的 `0.1.7-rc.2` 而不是 `0.2.0-rc.1`，于是「按新内核验证过」是假的。**必须钉精确版本。**
- **不要用 `pnpm install` 做常规验证**：它会重新解析依赖树，可能把 dev 依赖带到新内核。
  只是要绕过 pnpm 的前置依赖校验时，用
  `pnpm --config.verify-deps-before-run=false <script>`。

**遗留**：本地 `node_modules` 处于 pnpm 认为过期的状态，有终端时跑一次 `pnpm install` 即可。

### 5.4 `LICENSE`：无需动作，**原记录有误**（原 §二.4）

两条断言都被实测推翻：

- 「仓库根没有 `LICENSE`」→ 有。`eca123b`（scaffold）起就在，1064 B，MIT。
- 「npm 包里没有 LICENSE 文件」→ 有。npm 对根目录的 `LICENSE` / `LICENCE` **总是包含**，
